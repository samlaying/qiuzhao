# 能力迁移地图（产品 → 运营）

> 把产品经历里练出的能力，翻译成运营面试官听得懂的语言。面试时主动用右侧表述替代左侧。

| 产品向表述 | 运营向翻译 | 你已有的证据 |
|---|---|---|
| 需求分析、写 PRD | 用户洞察 + 需求挖掘 | 剪映音色克隆的痛点定位（声音身份丢失=留存流失 Top1） |
| 产品方案设计 | 策略/规则/机制设计 | VIP 权益定位、创作者分层灰度规则 |
| 项目推进、跨部门协作 | 推动执行、对齐目标节奏 | 协调算法/研发/客服推动 Bad Case 闭环 |
| 数据分析、看 AB | 指标运营 + 实验复盘 | A/B 900 万样本、付费率/转化率提升、投诉率复盘 |
| 功能上线、迭代 | 结果闭环 + 持续优化 | 上线后看使用率/投诉率，迭代至改善 92% |
| 竞品调研、市场分析 | 增长/渠道/商业化 sense | 美图证件照的 Top200 榜单扫描、CAC 对比 |

## 三条迁移心法

1. **从"我做了什么功能" → "我推动了什么业务结果"**：运营面试官要的是指标变化（GMV/转化/留存），不是功能清单。
2. **从"产品决策" → "策略+执行"**：多讲分层、规则、灰度、触达、复盘这些运营动作。
3. **从"交付" → "闭环"**：每个故事都要有"假设→执行→验证→迭代"的完整回路。
