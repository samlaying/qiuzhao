> | 步骤 | 动作 | 关键产出/验证 |

### Q2：这个项目是怎么从 0 到 1 启动的？

**面试官（推断）：这个项目是怎么从 0 到 1 启动的吗，还是在原有功能上迭代的？**

**林承列：**

美图是一个 P 图工具市场，我们在寻找新的产品增长点。在海外证件照这个市场上面，虽然现有的 AI 工具可以实现 P 图的功能，但没有任何一款真正的 AI 工具可以覆盖到主流国家的证件照要求。我们在这个市场空缺里判断出这个工具可以帮用户节省办理证件照的时间，就以这个为切入点在美图设计了这个功能。

> **答题要点 / 可复用框架**：0-1 启动题公式 = **找市场空缺 → 论证切入点 → 在现有产品里落地**。论证链路：现状（美图找新增长点、现有 AI 能 P 图）→ 空缺（无 AI 工具覆盖主流国家规格）→ 价值（帮用户省时间）→ 切入（APP 内新增功能）。
> - 「0-1」和「迭代」要先定性再讲故事。
> - 市场空缺的论证比功能描述更值钱——面试官想听「你为什么判断这事值得做」。
> - 切入点绑用户价值（省时间），不绑技术（我们有 AI）。

### Q6：MCP 和 CLI 的区别是什么？为什么要做 CLI？

**面试官（推断）：** MCP 和 CLI 有什么区别？为什么要把 MCP 做成 CLI？

**林承列：**

**MCP（Model Context Protocol）** 是一个协议层面的标准，定义了 LLM 怎么和外部工具/数据源交互。它解决的是"标准化接口"的问题——让不同的模型能用统一的方式调用工具。

**CLI（Command Line Interface）** 是交互形式，是给开发者用的命令行工具。

我们做 CLI 的原因：
1. **降低接入门槛** - 开发者不需要写 HTTP 请求、处理 SSE 流、管理会话状态，直接在终端跑命令即可
2. **调试友好** - 能直接看到输入输出，排查问题快
3. **自动化友好** - 可以写进 CI/CD、脚本里，做批量处理
4. **本地优先** - 数据不出本地，安全合规

简单说：MCP 是「标准」，CLI 是「分发形态」之一。我们把 MCP 能力包装成 CLI，是为了让开发者更容易用上这个标准。

> **答题要点 / 可复用框架**：技术选型题公式 = **先定义概念（分层）→ 再讲选型理由（场景驱动）→ 一句话收口**。
> - 概念分层：MCP = 协议层标准（LLM 如何调工具）；CLI = 交互/分发形态。二者不是替代，是**标准 × 分发形态**的正交关系。
> - 选型理由用「场景 + 收益」配对（降门槛/调试/自动化/本地安全），每条落到开发者具体痛点。
> - 最忌把不同层的东西直接对比。类似的"标准 vs 形态"判断（API vs SDK、协议 vs 实现）都能套这框架。延伸见 [[#Q9：MCP 和 Function Calling 有什么区别？]]。

### Q7：MCP 里的 Resource、Tool、Prompt 分别是什么？有什么区别？

**面试官（推断）：** MCP 里 Resource、Tool、Prompt 是什么概念？

**林承列：**

- **Resource（资源）**：只读数据源。比如文件内容、数据库记录、API 返回的数据。模型「读」它，不修改它。典型场景：RAG 检索到的文档片段、用户上传的 PDF 内容。
- **Tool（工具）**：可执行的动作。有副作用，会改变外部状态。模型「调用」它。典型场景：发送邮件、创建 Jira 票据、查询数据库并写入、部署服务。
- **Prompt（提示词）**：可复用的模板化指令。预设好的系统提示词或 few-shot 示例。模型「应用」它。典型场景：代码审查的标准 prompt、SQL 生成的 few-shot 模板。

区别核心：**读 vs 写 vs 指导**。Resource 给上下文，Tool 执行动作，Prompt 定行为模式。

> **答题要点 / 可复用框架**：概念辨析题 = **每概念一句定义 + 一个动词 + 一个场景 → 一句话压成记忆点**。
>
> | 原语 | 一句话 | 动词 | 副作用 | 典型场景 |
> |---|---|---|---|---|
> | Resource | 只读数据源 | 模型「读」 | 无 | RAG 文档片段、上传 PDF |
> | Tool | 可执行动作 | 模型「调用」 | 有（改外部状态） | 发邮件、建 Jira、写库、部署 |
> | Prompt | 模板化指令 | 模型「应用」 | 无（定行为） | 代码审查 prompt、SQL few-shot |
>
> 记忆口诀：读 vs 写 vs 指导。**"有没有副作用"是辨析 AI 原语的关键维度**——Resource/Prompt 无副作用，Tool 有。面试官爱追问"发邮件算 Resource 还是 Tool"→ 有副作用 → Tool。

## 第四部分：技术概念辨析

### Q9：MCP 和 Function Calling 有什么区别？

**面试官（推断）：** MCP 和 Function Calling 区别在哪？

**林承列：**

**Function Calling** 是模型层面的能力——模型原生支持输出结构化的函数调用请求（`{"name": "get_weather", "arguments": {"city": "Beijing"}}`），由模型提供商实现（OpenAI、Anthropic、各家开源模型）。

**MCP** 是协议层面的标准——定义了「客户端怎么发现工具、怎么调用工具、怎么获取资源、怎么用 prompt」。它不绑定特定模型，任何支持 MCP 的客户端都能连任何 MCP Server。

核心区别：
| 维度 | Function Calling | MCP |
|------|------------------|-----|
| 层级 | 模型能力 | 协议标准 |
| 绑定 | 强绑定模型厂商 | 模型无关 |
| 发现 | 模型训练时固定 | 运行时动态发现 |
| 传输 | 模型内部 | HTTP/SSE/stdio |
| 状态 | 无状态 | 支持会话、进度、取消 |

简单说：Function Calling 是「模型会用工具」，MCP 是「工具怎么被标准化描述和调用」。MCP Server 可以把 Function Calling 作为底层实现之一。

> **答题要点 / 可复用框架**：又是"层级对比"题（同 Q6 打法）。核心分层：Function Calling = 模型能力（绑定厂商）；MCP = 协议标准（模型无关）。一句话金句：**Function Calling 是「模型会用工具」，MCP 是「工具怎么被标准化描述和调用」，二者是上下层不是替代**。
> - 辨析相似技术先问"它们在同一层吗"。「绑定」与「状态管理」是高频对比维度。延伸 MCP 知识包：Q6、Q7、Q10。

### Q10：什么是 SSE？在 MCP 里怎么用的？

**面试官（推断）：** SSE 是什么？MCP 里怎么用？

**林承列：**

**SSE（Server-Sent Events）** 是基于 HTTP 的单向推送协议。服务端建立长连接，持续向客户端推送文本事件流（`data: ...\n\n`），客户端只负责接收。

在 MCP 里的作用：
- **传输层选择之一**：MCP 支持 stdio（本地进程通信）、HTTP+SSE（远程服务）、WebSocket
- **流式返回**：Tool 执行耗时长时，通过 SSE 分块推送进度、中间结果、最终结果
- **实时通知**：Resource 订阅变更、Prompt 模板更新、会话级通知

优势：比 WebSocket 简单，自带重连、浏览器原生支持、穿透代理友好。

> **答题要点 / 可复用框架**：先定义协议本质（基于 HTTP 的**单向推送**），再讲"在 X 里解决什么问题"，最后给相对优势。
> - 在 MCP 的三个作用：传输层之一（stdio/HTTP+SSE/WebSocket）、流式返回（长 Tool 分块推进度）、实时通知。
> - SSE vs WebSocket 经典对比：SSE 单向/文本/简单/HTTP 友好，WebSocket 双向/二进制/更重。只要服务端推、客户端不回传 → SSE 更划算。
> - 流式返回是 AI 产品核心体验——让用户看到进度而不是干等。

**核心定位**：海淀区程序员/实习生/应届生租房，痛点是「信息不对称」「假房源多」「通勤时间难评估」「合同坑多」。

**核心功能模块**：

1. **智能房源聚合与去重**
   - 多源抓取（链家、自如、贝壳、小红书、朋友圈、内部群）
   - 基于 地址+户型+房东/中介电话 做指纹去重
   - 真假房源打分：图片 EXIF、描述关键词、价格偏离度、发布频次

2. **AI 智能匹配推荐**
   - 用户画像：预算、工位坐标、通勤上限、生活习惯（作息、做饭、养宠）、硬性条件（整租/合租、朝向、楼层）
   - 房源画像：真实通勤时间（高德/百度地图实时路况）、周边设施向量、房东/中介信用分
   - 匹配算法：硬性过滤 → 向量相似度（生活习惯）+ 加权打分（通勤权重 40% + 价格 25% + 生活习惯 20% + 信用 15%）

3. **通勤可视化**
   - 一键生成「上班路线图」：地铁+步行、公交+骑行、打车三种模式实时耗时
   - 支持「多工位」场景（实习生可能轮岗、周末回学校）

4. **合同风险提示 & 电子签**
   - 标准条款库 + OCR 识别上传合同 → 风险条款高亮（违约金不对称、押金退还条件模糊、水电费计算不透明）
   - 接入电子签（e签宝/上上签），留存证据链

5. **社区评价体系**
   - 真实住户评价（入住 30 天后邀请）、小区维度画像（噪音、物业、网络、外卖覆盖）

**技术架构**：
- 数据层：Airbyte 同步多源 → ClickHouse 宽表
- 特征层：Flink 实时特征工程 → Feast 特征存储
- 模型层：双塔召回（用户塔+房源塔）+ LightGBM 精排
- 服务层：gRPC + GraphQL 聚合网关
- 前端：Next.js + Mapbox GL 通勤可视化

**冷启动策略**：
- 种子用户：内部员工、校招群、技术社区 KOL
- 种子房源：合作中介独家房源 + 自采真房源
- 激励：发真房源送会员、完善评价送积分兑换搬家券

> **答题要点 / 可复用框架**：产品设计题（0-1 系统）骨架 = **定位（给谁+痛点）→ 核心功能模块 → 技术架构 → 冷启动**。
>
> 本题四个亮点（多数候选人想不到）：
>
> | 亮点 | 为什么值钱 |
> |---|---|
> | 房源指纹去重 + 真假打分 | 直击"假房源多"，用 EXIF/价格偏离度多维信号，显数据 sense |
> | 真实通勤时间替代直线距离 | 租房真实决策因子是通勤不是距离；多工位是实习生特有洞察 |
> | 合同 OCR + 风险条款高亮 | 把"合同坑多"做成产品动作，不止停在发现痛点 |
> | 双塔召回 + 精排两段式推荐 | 懂推荐架构，不是只会说"用 AI 匹配" |
>
> 五条可迁移：① 先收窄人群痛点，别做"全人群平台"；② 每个痛点配一个产品动作，痛点↔功能一一对应；③ 匹配算法给权重（量化 trade-off）；④ 冷启动别忘（种子用户/房源/激励三件套）；⑤ 技术架构分层说（数据/特征/模型/服务/前端）。反问环节就用了这道题求反馈，见[[#第九部分：候选人反问环节]]。

## 第六部分：招聘平台数据模型设计

### Q12：设计一个招聘平台的核心数据模型

**面试官（推断）：** 如果让你设计招聘平台的核心表结构，你会怎么设计？

**林承列：**

**核心实体关系**：

```
User (用户)
├── Candidate (求职者) - 简历、投递记录、面试评价
├── HR (招聘方) - 公司认证、发布权限、数据看板
└── Interviewer (面试官) - 标签、校准记录、面试偏好

Company (公司) - 认证状态、规模、行业、品牌资料

Job (职位/JD) - 核心流转对象
├── 基础字段：标题、JD 正文、薪资范围、地点、工种、经验、学历、标签
├── 状态流转：草稿 → 审核中 → 发布中 → 暂停 → 关闭/过期
├── 统计字段：浏览数、投递数、面试数、录用数、平均响应时长
└── 版本管理：JD 修改历史、审核记录

Application (投递) - 核心链路事实表
├── 关联：candidate_id, job_id, hr_id
├── 状态：投递中 → 简历筛选 → 面试邀约 → 面试中 → Offer/拒绝 → 入职/流失
├── SLA 字段：各阶段截止时间、当前阶段停留时长
└── 评价：HR 备注、面试官评分、AI 匹配分

Interview (面试) - 面试轮次事实表
├── 关联：application_id, interviewer_id, round_id
├── 类型：电话/视频/现场、技术/业务/HR/交叉
├── 评价表单：结构化评分卡（维度+权重）、优缺点、录用建议
└── 校准：面试官校准会记录、一致性分析

Resume (简历) - 结构化存储
├── 原文存储（对象存储）
├── 解析字段：基本信息、教育经历、工作经历、项目经历、技能标签、证书
├── 版本管理：每次更新生成新版本、Diff 对比
└── 向量化：全文向量 + 分段向量（语义检索用）
```

**关键设计决策**：
- **Application 为核心事实表**，所有流程围绕它转
- **Job 版本化**：JD 修改不影响历史投递的匹配依据
- **Interview 解耦**：面试轮次配置化，支持动态增减轮次
- **软删除 + 审计日志**：合规要求，数据不物理删除

> **答题要点 / 可复用框架**：数据建模题骨架 = **核心实体关系 → 关键设计决策（为什么这么建）→ 合规/扩展性**。
> - 第一步找"核心事实表"——招聘平台是 **Application（投递）**，所有流程挂在它上面。最忌平铺所有表不分主次。
> - 四个关键决策：Application 为核心事实表（懂业务流转）、Job 版本化（懂数据一致性）、Interview 解耦（懂扩展性）、软删除+审计（懂合规）。
> - 状态机思维：Job 和 Application 都是状态机，显式画"状态流转"比堆字段更显业务理解。
> - 事实表 vs 维度表区分（Application/Interview 是事实表，User/Company/Job 是维度表）；合规考量（软删除/审计）一定要提。Resume 的结构化+向量化呼应 Q8 简历解析。

## 第七部分：个人贡献与竞争力

### Q13：你觉得你最大的竞争优势是什么？

**面试官（推断）：** 你的核心竞争力在哪里？

**林承列：**

三点：

1. **「产品+工程」双语言能力** - 不只画原型、写 PRD，能写 CLI、搭 MCP Server、跑 A/B 实验分析、看懂模型训练日志。在美图做海外证件照时，我自己写脚本跑竞品数据、自己配提示词实验、自己看转化漏斗；在猎聘做 MCP CLI 时，从协议读源码到发布 npm 包全程自己来。这意味着我能和研发「对齐技术边界」，少扯皮、少返工。

2. **「0-1 到 1-N」完整经历过** - 美图海外证件照是 0-1（竞品调研→形态定义→AB 实验→上线迭代，首月获客 10w+）；猎聘 MCP CLI 是内部工具 0-1 到推广 200+ 人用；租房平台设计题是现场 1-N 思维演练。我清楚每个阶段该关注什么指标、该砍什么需求、该怎么和业务方对齐预期。

3. **持续学习的「实战闭环」** - 不是看完论文/博客就算懂，而是「抓最新技术→跑通最小 Demo→接入真实场景→产出可复用资产」。最近半年：MCP 协议→写 CLI→内部推广 200+ 人；Agent 编排→写调度器→接入面试官工作台；RAG 优化→改检索/重排→上线简历匹配。每个循环都有「落地代码 + 业务指标 + 复盘文档」三件套。

> **答题要点 / 可复用框架**：竞争力题公式 = 每点「**能力标签 + 证据（项目+数据）+ 对岗位的价值**」，三点结构不堆砌。
>
> | 竞争力 | 证据 | 对岗位的价值 |
> |---|---|---|
> | 产品+工程双语言 | 美图写脚本/猎聘发 npm 包 | 能和研发对齐技术边界，少扯皮 |
> | 0-1 到 1-N 完整经历 | 美图 0-1/猎聘 0-1→推广/租房 1-N | 清楚每阶段关注什么指标、砍什么需求 |
> | 实战闭环学习 | MCP/Agent/RAG 三个闭环 | 落地代码+业务指标+复盘文档三件套 |
>
> 三点最好递进/互补：双语言（能力底座）→ 0-1到1-N（经历厚度）→ 实战闭环（成长引擎），覆盖"现在能做/做过什么/未来怎么持续"。差异化落在"别人没有的组合"上——竞争力 = 组合的稀缺性。

### Q14：你在项目中具体的贡献怎么界定？怎么证明是你做的？

**面试官（推断）：** 怎么界定你的贡献？怎么证明？

**林承列：**

**界定维度**：
- **决策权**：关键节点（形态定义、指标选取、技术选型、范围砍切）由我拍板
- **产出物**：PRD、原型、埋点方案、实验方案、上线清单、复盘文档——我是第一作者
- **跨团队拉通**：和算法对齐特征、和后端对接口、和运营定物料、和法务过合规——我是唯一对接人
- **兜底责任**：上线前最后一轮冒烟测试、上线后前 48 小时值班、出问题我写事后复盘

**证明方式**：
- Git 记录：核心仓库 commit 前 3、PR 作者、Review 通过率
- 文档链接：飞书文档/Notion 权限记录、创建时间、编辑历史
- 会议纪要：关键决策会议的妙记/录音、决策条目有我发言
- 业务指标：上线后指标看板截图、周报/月报里归属到我名下的数字
- 同事背书：Mentor、对接研发、对接运营可做交叉验证

> **答题要点 / 可复用框架**：贡献界定题 = **界定维度（怎么算我的）+ 证明方式（怎么证明）**，专治实习生"参与感强、主导感弱"。
> - 界定四维度（从轻到重）：决策权（最硬）、产出物（第一作者）、跨团队拉通（唯一对接人）、兜底责任（最显担当）。
> - 证明五件套（客观 > 主观）：Git（最硬）、文档权限/编辑历史、会议纪要/录音、业务指标归属、同事背书。
> - 最忌"协助/参与/支持"，要用"拍板/第一作者/唯一对接人/兜底"。证明靠客观留痕不是自述；"兜底责任"是最高级的贡献证明。提前理好每个项目的证据链，被追问能秒给链接。

## 第八部分：学习能力与个人特质

### Q15：你是怎么学习新技术的？（以 MCP 为例）

**面试官（推断）：** 你平时怎么学新东西？以 MCP 为例讲讲。

**林承列：**

**固定工作流**（已跑通 5+ 个技术循环）：

1. **源头锁定** - 官方 Spec（modelcontextprotocol.io/specification）、核心维护者 GitHub/推特、顶会 Paper/博客。不看二手解读、不看公众号爆款文。
2. **最小可跑通 Demo** - 30 分钟内跑通 Hello World。MCP 时：`npm create @modelcontextprotocol/server` → `stdio` 模式跑通 → 换 `SSE` 模式 → 接入 Claude Desktop 验证。
3. **真实场景接入** - 找一个手头痛点问题强行套用。MCP 时：把猎聘内部「查面试官日程」封装成 Tool，挂到 CLI 上，自己天天用。
4. **压力测试 & 边界探索** - 并发、超时、重试、取消、流式、错误码、鉴权、审计日志。MCP 时：并发 50 个客户端调同一个 Tool、模拟上游挂了看 Client 怎么降级。
5. **产出复用资产** - 封装成内部 SDK/CLI、写最佳实践文档、做分享会。MCP CLI 现在内部 200+ 人用，文档沉淀在飞书 Wiki。

**节奏**：新技术出现 → 第 1 天跑通 Demo → 第 3 天接入真实场景 → 第 7 天产出可复用资产 → 第 14 天复盘沉淀方法论。

> **答题要点 / 可复用框架**："怎么学"是最能拉开差距的题——多数人答"看文档/视频/做笔记"，你要给一套可复制的工程化工作流。
>
> 五步学习法（可迁移任何新技术）：① 源头锁定（只看一手）；② 最小 Demo（30min Hello World）；③ 真实场景（套到痛点天天用）；④ 压力测试（探边界）；⑤ 产出资产（SDK/文档/分享，从消费者变生产者）。
> - 给"节奏感"（1/3/7/14 天时间盒）证明学习是项目化的；"源头锁定不看二手"显信息品味；"产出复用资产"收口是最高级闭环；强调"已跑通 5+ 循环"证明是肌肉记忆。这也是 [[#Q13]] "实战闭环学习"竞争力的具体展开。

### Q16：你觉得你的学习能力怎么样？

**面试官（推断）：** 你的学习能力如何？

**林承列：**

特别是 AI 方面的学习能力，我觉得应该属于同龄人的前 90% 以上。具体体现在刚才说的整套工作流程——能够获取到最新知识、拿到最基础的落地实践、也能够形成自己的方法论。具体体现的话，平常和人交流时，一般是他们有问题我能够给予解答。所以学习能力是可以的。

### Q17：抗压能力怎么样？

**面试官（推断）：** 说说你的抗压能力。

**林承列：**

本质上是经验和注意力管理的方式，我觉得我的能力也算偏上。具体体现在最近的一段时间——Agent 项目遇到了一些出乎意料的事情，同时我还得兼顾学校上学期比较多的课业，最后还是表现得不错。英语六级 500 分，我就只能是这么一个量化的水平了。

## 第九部分：候选人反问环节

**林承列的提问：**

**问题一：** 我目前面试的岗位，它主要的工作职责以及对应的合作对象有哪些？有哪些需要特别注意的点？你认为我进来之后可能需要立即处理的困难是什么？有哪些事情需要额外注意？

**问题二：** 想听听老师对我刚刚设计的租房系统有什么评价？有哪些缺陷？

**问题三：** 这次面试的结果大体上什么时候会出？

> **答题要点 / 可复用框架**：反问环节是第二轮展示机会——展现主动、求反馈、关注落地。三个反问各有目的：
>
> | 反问 | 目的 | 展现的特质 |
> |---|---|---|
> | ① 岗位职责/合作对象/即时困难 | 摸清入职后真实工作 | 主动、关心落地、已在想怎么上手 |

> | ③ 面试结果何时出 | 了解流程 | 合理的流程关注（简短即可） |
>
> 反问至少备 2-3 个且要有质量（别问百度能查到的）；"请评价我刚才的回答/设计"是高分反问；反问要呼应前面人设；避免太功利/太空/"没问题"三类雷区；流程类反问放最后一句带过。

| MCP/CLI 项目 | 仅做概念解释 | 独立项目，含 MVP 验证、灰度方案、200+ 人才注册 | 面试中可能只被问到概念层面 |
| 面宝（黑客松） | 仅在自我介绍中一句话带过 | 简历中详细展开 SDD 驱动开发、产品设计、能力沉淀 | 面试中未被深挖 |
| 美图项目商业化 | 未提及 | "免费生成→付费高清下载"、B 端 API 接入（snapfoto/7-11） | 面试中未主动提及商业化策略 |
| 美图 A/B 实验细节 | "以 APP 大盘转化率为北极星指标" | 样本量 900 万、净付费率 +2.1%（p<0.05） | 面试中未给出量化数据 |
| 租房平台设计 | 有详细回答 | 简历中无此项 | 面试现场设计题 |

> **答题要点 / 逐项补救**：面试前必做——把简历每个数字背熟，确保口述能给出来且对得上。核心问题：**简历有硬数据，口述只给定性，等于把最有力的证据浪费了**。
>
> | 差异项 | 风险 | 补救动作 |
> |---|---|---|
> | 用户访谈"十几个" vs "30+" | 数字打架，诚信受损 | 统一以简历"30+"为准，别再说"十几个" |
> | MCP/CLI 只讲概念 | 错失展示独立项目 | 准备好 MVP 验证 + 灰度方案 |
> | 面宝未被深挖 | 主动埋钩子 | 自我介绍给面宝更具体钩子 |
> | 美图商业化没提 | 商业 sense 没展示 | 讲完美图功能后主动补商业化路径 |
> | 美图 A/B 没给量化 | 最硬证据没用上 | 主动报：900 万样本、+2.1%(p<0.05)、10w+ 获客 |
> | 租房设计简历无 | 无风险（现场题） | 沉淀进简历/作品集 |
>
> 通用原则：① 简历数字必须能"正反背诵"，口径不一致是诚信红线；② 量化数据主动报不等问；③ 建"数字清单"面试前过一遍；④ 转录 vs 简历差异主动收敛。
>
> ⚠️ 注：当前 [[110-产品-策略PM/02-个人项目/22-实习经历/在线简历]] 写的是字节·剪映 / 一起教育，与本面经的美图 / 猎聘不一致——可能是不同版本/时期简历。**面试前确认投这家用的是哪版简历，确保口述和那版完全对齐。**
