# 招聘场景下产品定位规划 — 对比笔记

## 一、三种形态总览

| 维度 | 终局形态（数字员工） | 过渡形态 A：身份过渡 | 过渡形态 B：工具过渡 |
|---|---|---|---|
| **核心概念** | Agent = 一个"人"（数字员工），占据一个岗位身份位，交互极简 | Agent 承担部分"人"的职责，但尚未完全替代岗位角色 | Agent 以工具/工作台形式存在，用户通过界面操作完成任务 |
| **交互方式** | 一个数字/一个人卡，类似找一个"真人"对话即可完成全部工作 | 介于工具和数字员工之间，Agent 能主动执行部分流程 | 工作台 + 功能面板，用户主导操作，Agent 辅助提效 |
| **对 Agent 能力要求** | 极强——通用人工智能水平，能调用各种接口，自主决策 | 较强——能在特定领域内自主完成多步任务 | 中等——聚焦于搜索、匹配等特定 Skill |
| **竞争格局** | 飞书、企微抢"身份位"入口（谁控制这个数字员工入口谁就赢） | 垂直 Agent 厂商的机会窗口期 | 当前主流 ATS（摩卡、北森）以及自研系统的战场 |
| **适用阶段** | 远期终态，需 Agent 能力持续突破 | 中期过渡，持续时间较长 | 当前阶段的现实落地方案 |
| **代表产品/类比** | OpenAI Operator 理想形态；飞书/企微未来形态 | 垂直招聘 Agent（我们的核心发力点） | 摩卡、北森等 ATS 系统；内部自研工具 |



## 二、按用户分层的产品定位对比

| 维度 | 大公司 HR（如华为、平安、快手） | 中型公司 HR | 中小企业 HR / 猎头 / 小公司业务方 |
|---|---|---|---|
| **公司特征** | 有专职 IT 团队，有采购预算，HR 是招聘第一责任人 | IT 支持有限，可能未采购高级 ATS | 无专职 IT，无 ATS 系统，HR 身兼多职 |
| **当前现状** | IT 团队自研招聘 Agent 或采购摩卡/北森等 ATS，正在"搞自己的龙虾"展现价值 | 部分有基础 ATS，但智能化程度低 | 完全依赖手动流程（Excel/表格/即时通讯） |
| **对 Agent 的需求** | 已有自己的 Agent 生态，只需要外部能力接入 | 有一定需求但缺乏实施能力 | 迫切需要，且无替代方案 |
| **我们的产品定位** | **仅提供 Skill**：搜索接口 + 匹配能力，封装为 Skill 供其 Agent 调用 | **有机会切入**：提供完整 Agent 产品，但需评估竞争 | **核心目标群体**：提供完整垂直招聘 Agent + 工作台 |
| **我们能提供的价值** | 底层能力输出（API/Skill），做"卖水人" | Agent 产品 + 行业 know-how | 全流程招聘 Agent，从搜索到匹配到跟进 |
| **竞争壁垒** | 低——可替代性强，客户自研能力强 | 中等——垂直专业度是差异化 | 高——客户无替代方案，粘性强 |
| **市场策略** | 生态合作，嵌入式集成 | 主动拓展，产品驱动 | 核心战场，全力投入 |

## 三、为什么"通用 Agent"现阶段不适用于招聘？

| 维度 | 通用 Agent（如 OpenAI Operator/ChatGPT） | 垂直招聘 Agent（我们的产品） |
|---|---|---|
| **交互形式** | 纯对话，极简入口 | 工作台 + 对话混合，渐进式信任建立 |
| **接口调用能力** | 弱——无法调用招聘系统内部接口、CRM、简历库等 | 强——深度对接招聘全流程 API |
| **HR 信任度** | 低——HR 需要"看得见摸得着"的工具来建立信心 | 高——可视化工作台降低使用门槛 |
| **适用阶段** | 终局形态，需 Agent 能力再跃升 | 当前阶段最优解 |
| **核心局限** | "很多人之前没接触过 Agent，认为它只能聊天"；给 HR 装上通用 Agent "根本用不起来" | 功能范围相对聚焦，但恰好覆盖高频需求 |
| **用户心智** | 需要漫长的教育过程 | 贴合 HR 已有的工作流认知 |

## 四、核心逻辑链总结

```
终局 = 交互极简 → 对 Agent 能力要求极高 → 飞书/企微抢身份位入口
                                              ↑
过渡期很长 ← Agent 能力尚未突破 ← 当前阶段现实
                                              ↓
机会窗口 = 垂直招聘 Agent（工作台形态）
              ↓
        面向：中小企业 HR / 猎头 / 小公司业务方
              ↓
        策略：对大公司只输出 Skill（搜索+匹配）
              对中小公司输出完整 Agent 产品
```

## 五、关键原话提炼

| 要点 | 原话 |
|---|---|
| 交互与能力的关系 | "交互足够简单 → 对 Agent 的能力要求更强" |
| 通用 Agent 的现状 | "给内部的 HR 装上 OpenAI Operator，他根本用不起来" |
| 终局竞争格局 | "飞书、企微都会抢这个身份位" |
| 大公司的定位 | "我们的空间没有 Agent，只能够提供 Skill" |
| 大公司的现状 | "大公司的 IT 要展现自己的价值，一定会给 HR 搞一个 Agent" |
| 中小企业是主战场 | "大部分公司的 HR 没有 IT 提供后装，也没有采买摩卡北森" |
| 为什么需要工作台 | "Agent 能力还没那么强，需要逐步建立信任，需要中间过程" |
| 产品适配性 | "OpenAI Operator 不适用于他们，垂直招聘 Agent 适用于他们" |
