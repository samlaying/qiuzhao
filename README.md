# 秋招面试准备资料库

这是一个以“原始材料 → 知识编译 → 岗位准备 → 面试复盘 → 持续回流”为主线的 Obsidian 知识库。

快速入口：[[00-开始这里]]。日常从根目录的 `100-` 到 `200-` 编号文件夹进入；每个岗位文件夹都包含该岗位的准备、面经、录音、复盘和训练入口。

## 新目录结构

```text
00-系统/       规则、模板、Schema、工作流
10-原始材料/   未整理的面经、JD、课程、截图和转写
110-170/      各岗位完整准备包（项目、知识、题库、面经、复盘、训练）
190-产品公司专项/ 公司和转岗材料
300-面试材料/ 面试材料总入口
10-原始材料/  原始录音、面经、JD 和文章
60-面试事件/  后台面试事件源材料
70-训练评测/  训练与评测（分三类，见下）
90-归档/       过期内容和历史版本
```

## 评测分类

`70-训练评测/` 下三类评测物理分开，互不混放：

| 类别 | 位置 | 用途 |
|---|---|---|
| 面试回答评测 | `71-回答训练/` ~ `75-回归结果/` | mock 回答的训练、打分、Bad Case、回归 |
| AI/Agent 评测 | `74-评测数据/评测准备/` | 大模型/Agent 评测集设计与方法论 |
| 行测模考 | `77-行测模考/` | 笔试行测模考与复盘（言语理解 / 判断推理 / 数资资料） |

新内容先确认类别，再落到对应目录，不要交叉混放。

## 使用方法

新材料统一放入 `10-原始材料/`，不要直接放进项目、题库或岗位目录。

处理流程：

```text
放入原始材料 → 自动识别 → 生成编译产物 → 建立双向链接 → 更新索引 → 复盘回流
```

## 核心入口

- 每个岗位的完整入口：`110-` 至 `170-` 根目录岗位文件夹
- 原始材料入口：[[10-原始材料/19-待分类]]

## 整理原则

1. 原始内容不覆盖，只生成整理稿。
2. 个人事实、通用知识、题库回答和岗位准备互不替代。
3. 同一份原始材料可以产生多个编译产物，但所有产物必须保留来源。
4. 低置信度内容进入待处理队列，不自动污染核心知识。
5. 旧内容先归档，不直接删除。
