## 一、项目背景与定位

### 大背景
抖音全球化布局下，短视频创作者对跨语言内容的需求增加。剪映AI视频翻译工具链已有三大模块：**语音识别 → 文字翻译 → 智能口型**，在此基础上新增**音色克隆**功能，形成完整的AI配音产品矩阵。
### 商业化目标
- 提升用户粘性
- 提升VIP付费转化率（音色克隆属于VIP权益功能）
### 技术定位
采用**低资源音色克隆技术**，核心是"轻量化高精度"。
**决策逻辑：**
- 模型有两个核心维度：①效果精度 ②产出时长/推理效率
- 短视频用户习惯决定了不能为了精度牺牲流畅度（卡顿直接影响创作体验）
- 因此选择"轻量化高精度"方案 — 追求效果好但不过度追求极致精度，同时保证推理速度
- 用户采样门槛定为**1分钟以内原声**，降低使用门槛，提高使用率

**关于模型选型（面试口径建议）：**
- 统一表述为：**基于字节自研TTS模型，融合低资源克隆技术优化**
- 如被追问，可补充：前期调研了行业主流模型（科大讯飞、阿里、MiniMax等），从准确率、响应速度、成本三个维度对比评估后选定方案
- 主动说明：调研工作在入职前已完成，但自己主动学习了解了评估逻辑和维度
- 若被问到具体数值，可模糊处理："我记得大概准确率在90%左右，但具体数据不是我主导调研的，记得不太精确"


## 二、产品交互设计

### 用户操作流程（完整路径）

```
进入页面 → 点击音色克隆 → 导入视频 → 选择语言 → 授权音色克隆 → 克隆处理 → 进度展示 → 保存使用
```

### 进度展示的具体逻辑

| 要素       | 说明                                  |
| -------- | ----------------------------------- |
| **展示方式** | 实时显示克隆进度百分比（如"克隆中…67%"）             |
| **目的**   | 提升用户的操作感知和等待耐心，避免用户因不确定感而中途退出       |
| **设计考量** | 音色克隆需要一定的算法处理时间，如果没有进度反馈，用户会以为卡死而退出 |

### 失败重试机制的具体逻辑

**失败场景：**
- 用户上传的音频咬字模糊/不清晰
- 音频质量不达标（噪音过大、音量过低等）
- 其他技术异常

**重试机制设计：**
1. **失败判定**：系统检测到音频质量不达标或克隆失败时，触发失败状态
2. **提示反馈**：向用户展示明确的失败原因（如"音频不清晰，请重新录制"）
3. **重试入口**：提供一键重试按钮，用户可重新上传音频再次克隆
4. **兜底方案**：多次重试仍失败时，引导用户联系客服进行人工处理

**决策逻辑：** 克隆失败是直接影响用户体验和投诉率的核心痛点，必须有完善的重试和兜底路径，不能让用户"卡死"在流程中。



## 三、内部评测

### 测试规模
- **5000个样本**
- 覆盖**10个典型场景**（如：录屏、口播、影视片段、跨境电商术语、直播喊麦、不同语速、不同行业等）

### 三项核心指标定义与计算口径

#### 指标一：克隆成功度
| 维度 | 说明 |
|------|------|
| **定义** | 衡量音色克隆功能的"能不能跑通" |
| **公式** | `克隆成功次数 ÷ 克隆总次数` |
| **分子** | 克隆成功的次数 |
| **分母** | 所有发起克隆的总次数 |
| **性质** | 率（百分比） |

#### 指标二：可用度
| 维度     | 说明                        |
| ------ | ------------------------- |
| **定义** | 衡量克隆成功后"用户愿不愿意用"          |
| **公式** | `克隆成功后用户实际使用的次数 ÷ 克隆成功次数` |
| **分子** | 克隆成功且用户实际授权用于配音的次数        |
| **分母** | 克隆成功的次数                   |
| **性质** | 率（百分比）                    |

#### 指标三：音色还原质感分
| 维度         | 说明                                                |
| ---------- | ------------------------------------------------- |
| **定义**     | 衡量克隆音色与用户原声的还原程度                                  |
| **计算方式**   | 算法打分（60-100分区间） + 人工抽检校验                          |
| **具体流程**   | ①算法将克隆音频与用户原声对比，自动给出分值 ②人工抽检验证算法分数的合理性            |
| **人工抽检逻辑** | 设定阈值（如80分以上认为用户可用），随机抽取80分以上的样本进行人工听感检验，确认合格率是否达标 |
| **性质**     | 分值（不是率）                                           |

**三个指标的关系递进逻辑：**
> 成功度（能不能跑通）→ 可用度（用户用不用）→ 质感分（效果好不好）


## 四、灰度上线策略

### 分批策略

```
MVP跑通 → 内部小规模场景测试 → 灰度分批上线（+ AB实验）
```

**具体步骤：**

| 阶段 | 做法 | 目的 |
|------|------|------|
| **第一步：MVP跑通** | 内部验证技术可行性 | 确保基本功能可用 |
| **第二步：场景化测试** | 面向内部，覆盖10大场景5000样本 | 全面评估效果，发现初步问题 |
| **第三步：灰度上线** | 首批开放**10%-20%核心创作者**，同时设对照组 | 小范围验证线上表现 |
| **第四步：逐步扩量** | 根据反馈和数据表现逐步扩大开放比例 | 稳步推进，控制风险 |

**灰度 + AB实验设计：**
- 圈选20%核心创作者，分为实验组（有音色克隆功能）和对照组（无该功能）
- 对比两组的付费转化率等核心指标
- 面试口径：实验组相较对照组VIP付费转化率提升**3.7%**（建议表述为1.7%留有余地）

**地域维度（备答）：** 可按分批次、分地域逐步放开，但面试中先不主动展开，被问到再补充。



## 五、迭代优化

### Bad Case 分类

灰度上线后收集到的核心Bad Case主要分两类：

| Bad Case类型 | 具体表现                     |
| ---------- | ------------------------ |
| **音色失真**   | 克隆出来的声音与原声差异大，用户感知"不像自己" |
| **克隆失败**   | 技术层面未能成功完成克隆（音频质量问题等）    |

### 优化策略（产品+算法协同）

**迭代流程：**

```
收集Bad Case → 产品分类归因 → 算法针对性优化模型 → 人工兜底客服响应
```

| 步骤                | 主导方    | 具体做法                               |
| ----------------- | ------ | ---------------------------------- |
| **1. 收集Bad Case** | 产品     | 从灰度用户的反馈、投诉中系统性收集失败案例              |
| **2. 分类归因**       | 产品     | 按问题类型分类（音色失真 / 克隆失败 / 质感差等），分析根因   |
| **3. 算法优化**       | 算法（主导） | 基于产品分类结果，针对性迭代模型，优化对应场景的克隆效果       |
| **4. 人工兜底**       | 客服+产品  | 对于无法自动解决的case，设置人工兜底机制，用户可一键联系客服处理 |

**关键点：** 产品负责"发现问题和定义问题"，算法负责"解决问题"。面试表述时强调这是**产品主导收集分类、算法主导技术优化**的协同模式。

### 迭代成果

| 指标           | 迭代前  | 迭代后  | 改善幅度   |
| ------------ | ---- | ---- | ------ |
| 用户投诉率        | 7.2% | 1.8% | 下降约75% |
| 核心痛点（音色失真）改善 | —    | —    | 改善92%  |
