# AI产品经理面试——硬实力（Hard Skills）准备笔记

---

## 核心问题：面试为什么"平"？

> 大多数候选人准备的模子和标准高度相似，容易在横向对比中被淘汰。根本原因：**不知道该把重心放在哪里。**

---

## 三大重点方向

---

### 一、体现对最新技术应用的**实践认知**

#### 误区

- 不要堆砌技术名词
- 不要复述面试官用大模型就能查到的定义

#### 正确做法

> 从底层理解清楚：**新技术到底解决了当前产品的什么问题？对产品设计有什么影响？**

#### 案例：以 Agent（智能体）为例

**不要只讲概念**（上下文、工具调用、记忆、路由、评测、权限、异常处理分别是什么）。

**要讲落地实践中的真实问题：**

| 落地环节 | 具体问题 |
|---|---|
| 权限设计 | Agent 能不能自主触达用户（如通过企微发消息）？主动创建跟进任务？ |
| 工具调用 | 客户资料是照片→能不能做 OCR 解析？能不能修改客户状态？ |
| 信息处理 | 历史聊天记录怎么处理？近期信息怎么处理？如何判断商机阶段？ |
| 路由/决策 | 如何基于客户信息生成下一步建议？如何调用正确的工具？ |

**场景还原（销售助手）：**

Agent 要完成真正的销售任务 → 需要：读取客户资料 + 分析历史沟通 + 判断商机阶段 + 生成下一步建议 + 主动触达用户（权限）+ 创建跟进任务 + 更新CRM系统。

#### 准备方法论：围绕 4 个问题准备

| # | 问题 | 目的 |
|---|---|---|
| 1 | 这种新技术**出现的原因**是什么？ | 理解技术演进的驱动力 |
| 2 | 它**解决了**落地过程中的什么问题？ | 理解实际价值 |
| 3 | 它**会改变**哪些产品设计？ | 理解对产品的影响 |
| 4 | 它在**什么场景下有价值**？什么场景下**没有必要**使用？ | 体现判断力和边界感 |

> **核心原则：准备的不是定义，而是"实践的认知"。**

---

### 二、至少讲 1 个**让模型在业务场景达到最优效果**的案例

#### 这个案例要同时体现：

- ✅ 你对**业务**的理解
- ✅ 你对**AI**的理解
- ✅ 你对**AI落地与业务结合**的理解

#### 误区

- 不要把重点放在介绍功能上

#### 讲清楚的核心四点

| # | 讲什么 | 体现什么能力 |
|---|---|---|
| ① | **为什么这个场景一定要用AI？** | 对模型边界的理解、对需求的理解 |
| ② | **模型一开始为什么做得不好？原因是什么？怎么分析的？** | 问题拆解与诊断能力 |
| ③ | **基于这些问题，用了什么策略进行优化？** | AI产品方法论与工程化能力 |
| ④ | **如何通过评测驱动产品迭代？** | 数据驱动的产品迭代思维 |

#### 案例演示：简历优化产品

**① 为什么用AI？**（此处可自行展开）

**② 模型一开始为什么做得不好？拆解三个问题：**

| 问题 | 具体表现 |
|---|---|
| **需求不明确** | 模型不知道用户投什么岗位→建议太通用，无法给出针对性指导 |
| **信息过载** | 模型同时提出大量修改意见→用户不知道优先改什么、改到什么程度 |
| **幻觉问题** | 模型改出来的内容虽然流畅，但偏离用户真实经历，编造了不存在的内容 |

**③ 优化策略：**

- 通过**意图识别**识别用户最核心的需求
- 针对核心需求**针对性地给建议**（而非全面轰炸）
- 对生成内容做**事实性校验**，约束模型不编造经历
- （此处可补充prompt设计、RAG、fine-tuning等具体手段）

**④ 评测体系与迭代：**

- 如何搭建评测体系？
- 评测结果如何推动产品迭代？

> **核心原则：讲一个完整的"发现问题→分析根因→制定策略→评测迭代"的闭环逻辑。**

---

### 三、体现对**新产品**的敏感度与深度

#### 误区

- 不要只停留在体验层或用户数据层面

#### 真正的产品敏感度——从一个新产品中快速判断 6 个点：

| # | 判断维度 | 关键问题 |
|---|---|---|
| 1 | **为什么现在出现？** | 时间窗口为什么是此刻？市场/技术/用户发生了什么变化？ |
| 2 | **抓住了什么新的技术能力？** | 底层技术突破是什么？它使什么成为可能？ |
| 3 | **什么决定了它的产品设计？** | 为什么产品形态是这样而不是那样？设计背后的取舍是什么？ |
| 4 | **可能改变什么用户行为？** | 用户习惯/预期会发生什么迁移？ |
| 5 | **哪些是真正的创新 vs 模型能力升级的自然结果？** | 区分产品创新与技术红利 |
| 6 | **对当前业务有什么启发？** | 可借鉴/可复用的点是什么？ |

> **核心原则：不停留在"好不好用"，而是追问"为什么"和"所以呢"。**

## 总结：三类硬实力的底层逻辑

```
┌─────────────────────────────────────────────────────┐
│           AI产品经理面试·硬实力三支柱                  │
├───────────────┬──────────────────┬──────────────────┤
│  技术理解深度   │  落地实践深度     │  产品敏感深度     │
│               │                  │                  │
│ 不讲名词       │ 不讲功能         │ 不讲体验         │
│ 讲实践认知      │ 讲优化闭环       │ 讲底层判断       │
│               │                  │                  │
│ 4个问题:       │ 4个核心点:       │ 6个判断维度:      │
│ ·为什么出现    │ ·为什么用AI      │ ·为什么现在出现   │
│ ·解决什么问题  │ ·为什么做不好    │ ·什么技术能力     │
│ ·改变哪些设计  │ ·怎么优化的      │ ·设计怎么决定的   │
│ ·什么场景有价值│ ·评测怎么驱动    │ ·改变什么行为     │
│               │                  │ ·创新vs技术红利   │
│               │                  │ ·对业务的启发     │
└───────────────┴──────────────────┴──────────────────┘
```

---

**一句话记忆法：**

> 面试不"平"的关键 = **技术讲落地、案例讲闭环、新品讲本质。**
