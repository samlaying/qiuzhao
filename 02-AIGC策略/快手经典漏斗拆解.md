## 一、整体架构：一个"层层过筛"的漏斗

你发的这张图非常经典，是工业界标准的**多级漏斗架构**。核心思想就一句话：**用尽可能少的计算量，逐步缩小候选范围，最后把最可能让用户喜欢的内容挑出来。**

```
全量视频库（几亿条）
    ↓
请求池（候选视频集，几千万条在线可用）
    ↓ 【召回层】粗筛，速度快，算力省
召回结果（几百~几千条）
    ↓ 【粗排层】快速打分，初步排序
粗排结果（几十~几百条）
    ↓ 【精排层】精细打分，精准排序
精排结果（十几~几十条）
    ↓ 【重排层】业务策略、多样性、混排
最终曝光列表（10条左右）
    ↓
用户看到 → 点击/播放 → 完播 → 互动 → 留存
```

**为什么要分这么多层？** 因为如果把几亿条视频都拿去做精细计算，服务器会炸。就像相亲不可能把全城人都见一遍，先通过条件筛选，再逐步深入了解。



## 二、逐层详解（从策略PM视角）

### 1. 请求池（Request Pool）——"候选视频集"

**是什么：** 不是全量视频库，而是**当前在线、可推荐**的视频集合。快手每天有1500万+新视频上传，但不是所有视频都能被推荐。

**怎么构建：**
- **准入规则**：新视频过审、画质达标、不违规
- **汰换规则**：发布时间太久（如30天前）、播放量极低、被多次举报的视频会被踢出池子
- **分层池子**：可能有"新内容池"、"高热内容池"、"长尾内容池"等

**策略PM的关注点：**
- 池子大小直接影响推荐多样性。池子太小，用户看来看去就那些；池子太大，召回压力大
- 冷启动内容（新视频）的准入门槛怎么设？太低容易出劣质内容，太高新作者没流量



### 2. 召回（Recall）——"海选阶段，不能漏"

**核心目标：** 从几千万视频里，**快速**捞出几百到几千条"可能相关"的视频。**速度第一，宁可错杀不可漏杀**（后续还有排序层把关）。

**为什么叫"召回"：** 就像搜索引擎，你输入关键词，它把包含关键词的网页都"召回"回来。

**快手的多路召回（Multi-Channel Recall）：**
快手不会只用一个方法召回，而是**多路并行**，每路召回几百条，最后合并去重。

| 召回路               | 原理                | 举例                            |
| ----------------- | ----------------- | ----------------------------- |
| **协同过滤**（UserCF）  | 找跟你相似的用户，看他们喜欢看什么 | 用户A和用户B都喜欢看美食视频，A看了某个新视频，也推给B |
| **ItemCF**        | 看你历史喜欢的视频，找相似视频   | 你刚看完"红烧肉做法"，召回"糖醋排骨做法"        |
| **向量召回**（DSSM/双塔） | 把用户和视频都变成向量，找距离近的 | 用深度学习模型计算用户兴趣和视频内容的匹配度        |
| **热门召回**          | 推全站高热内容           | 当前最火的"淄博烧烤"视频                 |
| **关注召回**          | 推你关注作者的新视频        | 你关注的博主更新了                     |
| **同城/LBS召回**      | 基于地理位置            | 推附近的人发的视频                     |
| **冷启动召回**         | 专门给新用户/新视频        | 新注册的用户推大众化内容；新视频推给可能感兴趣的人     |

**技术细节（小白了解即可）：**
- 向量召回通常用 **Faiss** 做近似最近邻搜索（ANN），毫秒级返回结果
- 每路召回有个"配额"，比如协同过滤召回500条，热门召回200条，最后合并去重

**策略PM的关注点：**
- **各路召回的权重/配额怎么分配？** 比如发现最近用户更关注熟人社交，是否增加"关注召回"的配额？
- **新召回路怎么评估？** 上线一路新的召回（比如基于知识图谱的召回），怎么衡量它对整体效果的增益？
- **冷启动问题：** 新用户没有历史行为，召回怎么保证不全是热门视频？



### 3. 粗排（Coarse Ranking）——"初筛，快速过滤"

**核心目标：** 从召回的几千条里，快速选出几百条给精排。**兼顾精准和速度**。

**为什么需要粗排？** 召回返回的数量还是太多，如果直接给精排，精排模型太复杂，计算量扛不住。

**常用方法：**

**① 基于规则的粗排（简单场景）：**
- 各路召回有个分数，直接加权求和。比如：协同过滤分数×0.4 + 热门分数×0.3 + 向量召回分数×0.3
- 或者按单一指标排序：近7天播放量、CTR等

**② 基于模型的粗排（工业界主流）：**
- 用一个**轻量级模型**（如双塔模型、浅层DNN）快速预估CTR
- 特征比精排少，模型比精排简单，推理耗时控制在**几毫秒**内

**快手实践：** 粗排通常用双塔结构（用户塔+物品塔），线上推理耗时控制在8ms以内。

**策略PM的关注点：**
- 粗排模型和精排模型的**一致性**。如果粗排认为好的视频，精排打分很低，说明两层目标不一致，需要调优
- 粗排截断数（Top K）怎么设？K太大精排压力大，K太小可能漏掉好内容



### 4. 精排（Fine Ranking）——"核心战场，精准排序"

**核心目标：** 对粗排送来的几百条视频，进行**最精细的打分排序**，选出最优的十几到几十条。**这是推荐系统的"心脏"**。

**为什么最重要？** 因为前面的召回和粗排都是"快速筛选"，精排才是真正决定"用户看到什么"的关键。

**快手的内容推荐场景——多目标排序：**
不同于电商主要优化CTR（点击率），快手这类短视频平台要优化**多个目标**：

```
排序分数 = a×P(播放) + b×P(点赞) + c×P(评论) + d×P(分享) + e×P(关注) + f×时长...
```

- **P(播放)**：预估用户会点击播放的概率
- **P(点赞/评论/分享)**：预估互动概率
- **时长**：预估观看时长（通常用专门的模型或公式处理）
- **a,b,c,d,e,f**：超参数，由策略PM和算法工程师一起调

**常用模型（了解名词即可）：**
- **LR/GBDT+LR**：经典方案，解释性强
- **Wide&Deep / DeepFM**：兼顾记忆性和泛化性
- **DIN / DIEN**：考虑用户历史行为序列，捕捉动态兴趣
- **MMoE / PLE**：多任务学习，专门处理多目标优化

**特征工程（策略PM的主战场）：**
精排效果很大程度上取决于特征。常见特征类型：

| 特征类型 | 举例 |
|----------|------|
| 用户特征 | 用户ID、性别、年龄、地域、活跃时间段、兴趣标签 |
| 视频特征 | 视频ID、作者ID、类目、标签、时长、清晰度、发布时间 |
| 上下文特征 | 请求时间、网络环境、设备型号、当前场景（首页/同城/关注） |
| 交叉特征 | 用户最近看的类目 × 视频类目、用户活跃时间 × 视频发布时间 |
| 行为序列 | 用户最近点击的10个视频ID序列（用DIN/DIEN建模） |

**策略PM的核心工作：**
- **定义优化目标：** 公司现阶段是冲DAU还是冲时长？是冲互动还是冲留存？这决定了多目标公式里的权重
- **特征设计：** 提出业务假设，设计新特征。比如"用户最近3天对美食类视频的完播率"是否对预测有帮助？
- **样本选择：** 精排的正样本是"曝光且点击"，负样本是"曝光未点击"。但要注意**样本偏差**（SSB）问题



### 5. 重排（Re-ranking）——"最后调整，业务策略落地"

**核心目标：** 精排出品的是"最优单品"，但重排要考虑**整个列表的体验**和业务诉求。

**为什么需要重排？** 精排只考虑单个视频的好坏，不考虑：
- 连续3个视频都是同一个人发的，用户会烦
- 连续5个都是美食视频，用户会审美疲劳
- 平台想扶持新作者，但精排打分低，需要"提权"
- 广告、直播、图文等多种内容怎么混排

**重排的主要工作：**

**① 去重/过滤：**
- 去掉用户已经看过的视频
- 去掉用户明确点过"不感兴趣"的作者/类目

**② 多样性（Diversity）：**
- **类目打散：** 不能连续出现同类目视频。比如最多连续2个美食视频，接下来必须插一个其他类型
- **作者打散：** 不能连续3个视频都是同一个作者
- **内容形式打散：** 短视频、直播、图文间隔出现

**③ 业务策略干预：**
- **流量扶持：** 新作者、特定活动话题的视频加权
- **降权/打压：** 低质内容、争议内容降权
- **强插/定坑：** 第3位固定插广告，第5位固定插"关注"模块
- **混排：** 自然推荐内容 + 广告 + 直播 + 电商商品 怎么组合

**④ 序列优化（List-wise）：**
传统精排是Point-wise（逐个打分），但重排可以考虑**上下文影响**。

快手实践：采用 **Generator-Evaluator** 范式：
- **Generator：** 从Top 50视频中生成多种排列组合（如Beam Search）
- **Evaluator：** 用Transformer模型评估整个序列的价值（播放时长、是否下刷、互动率）

**举个例子：**
精排结果：[视频A(美食), 视频B(美食), 视频C(旅游), 视频D(美食)]
重排后可能变成：[视频A(美食), 视频C(旅游), 视频B(美食), 视频D(搞笑)]
虽然B和D的单体分更高，但连续美食视频体验差，打散后整体序列价值更高。

**策略PM的核心工作：**
- **制定打散规则：** 同类目最大连续出现次数、同作者间隔几个视频
- **流量分配策略：** 新作者扶持比例、垂类内容（如知识类）流量占比
- **混排策略：** 广告间隔几个自然内容？直播卡片怎么插？
- **A/B实验：** 重排策略最容易做实验，因为直接调整规则即可



### 6. 曝光 → 后续行为——"数据回流，闭环优化"

用户看到推荐列表后，会产生一系列行为，这些数据会回流，用于优化上游各层模型：

```
曝光（Impression）→ 点击/播放（Click/Play）→ 完播（Completion）→ 互动（Like/Comment/Share）→ 长期留存（Retention）
```

**关键指标：**
- **CTR（点击率）** = 点击 / 曝光
- **完播率** = 完播次数 / 播放次数
- **互动率** = 互动次数 / 播放次数
- **人均时长** = 总观看时长 / 用户数
- **次日留存率** = 次日仍活跃的用户 / 今日活跃用户

**数据回流闭环：**
用户行为 → 埋点上报 → 数据清洗 → 生成训练样本 → 模型训练 → 模型更新 → 在线服务



## 三、作为策略PM，你在每层能做什么？

| 层级      | 策略PM的核心工作                      | 需要懂的技术             |
| ------- | ------------------------------ | ------------------ |
| **请求池** | 制定准入/汰换规则、冷启动策略、池子分层策略         | 理解内容审核、基础数据统计      |
| **召回**  | 规划召回路（如新增社交召回）、分配各路配额、评估召回效果   | 理解召回原理、HitRate评估   |
| **粗排**  | 制定粗排规则、协调粗排与精排的一致性             | 理解模型目标、AUC评估       |
| **精排**  | **定义优化目标（多目标权重）、设计特征、选择样本、调参** | 理解多目标学习、特征工程、A/B测试 |
| **重排**  | **制定打散规则、流量扶持策略、混排策略、业务强插规则**  | 理解多样性算法、序列优化、规则引擎  |
| **全链路** | 分析漏斗转化率、定位问题环节、协调算法/工程/运营      | 数据分析、SQL、实验设计      |



## 四、快手的一些特殊实践

根据搜索结果，快手在推荐系统上有几个值得注意的点：
1. **平等普惠价值观：** 快手强调不把所有流量都给头部作者，会在重排层对新作者、中小作者进行流量扶持，这直接影响重排策略的设计。
2. **端上重排：** 快手在客户端（手机端）也部署了重排模型，可以实时感知用户反馈（如下滑行为），及时调整后续推荐，减少服务端请求压力。

3. **多源混排：** 快手有短视频、直播、广告、电商等多种内容形态，重排层需要解决"怎么混"的问题，从简单的定坑规则进化到强化学习方案。

4. **算力优化：** 快手提到传统多阶段流水线存在算力浪费问题（GPU利用率低），正在探索"召粗精一体"的模型架构，这是未来的技术趋势。
