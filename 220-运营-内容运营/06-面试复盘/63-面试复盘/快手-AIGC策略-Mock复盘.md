## 一、面试评价撰写规范

### 1.1 核心原则：客观、可验证、抓硬伤

- 评价应聚焦 **可验证的硬伤类问题**，而非主观感受。
- 挂人的关键点要写清楚，否则可能被 HR 追问甚至打差评。
- **HR 有权向招聘方询问挂人原因**，如果评价写得模糊或带有主观情绪，容易引发投诉，甚至导致该候选人被列入"不可招"名单。

### 1.2 三大硬伤类别

| 硬伤类型 | 说明 |
|---|---|
| **用户理解不足** | 无法准确识别目标用户、需求场景或痛点 |
| **策略理解不足** | 无法将问题拆解为可执行的策略路径 |
| **数据理解不足** | 无法用数据量化问题、衡量效果或做合理预估 |

> 讲师原话："我一般只会写几个点，要不你对用户理解不足，要不你的策略理解不足，要不你的数据理解不足——随便挂一个都是硬伤。"

### 1.3 反面示例（不要这样写）

- ❌ "太啰嗦"
- ❌ "没有结构化"
- ❌ "表达不清楚"

这些表述无法在事后回忆和验证，面试官也无法解释清楚"他到底说了什么让你觉得没结构化"。

### 1.4 正面示例

- ✅ "未抓住面试题目重点"
- ✅ "未能将用户痛点量化为可执行策略"
- ✅ "对目标用户群体的生命周期阶段判断有偏差"

## 二、策略产品经理岗位特性

### 2.1 与社区/C端/功能型产品岗的区别

| 维度 | 策略产品 | 社区/C端/功能型产品 |
|---|---|---|
| 思维模式 | 宏观系统性，统计学视角 | 微观场景化，用户故事驱动 |
| 决策依据 | 数据指标、漏斗拆解、趋势判断 | 用户反馈、场景洞察、直觉 |
| 表达方式 | 先亮指标目标，再拆解路径 | 先讲故事/场景，再推导方案 |
| 试错方式 | 需要有共识基础（"跟风"性质），不能凭空试 | 可以"先往这个方向试试" |

### 2.2 策略岗面试的关键考察点

1. **指标提升目标**：你要提升哪一块数据？目的是什么？（必须前置说明）
2. **漏斗式逻辑拆解**：用了什么思考逻辑？痛点如何量化成执行策略？
3. **内容生态与用户趋势的判断**：方向判断偏差会被视为"生态理解缺失"
4. **Case Study**：是策略岗面试的核心环节，重点在于展现业务洞察与策略闭环能力，而非复述过往项目

> 讲师原话："社区产品可能问你以前做了什么就行了，但策略岗不会，Case Study 是一个很重要的项目。"

## 三、业务题拆解方法论（以"视频化"为例）

### 3.1 三层递进框架

```
┌─────────────────────────────────────────┐
│  第一层：用户视角（最高优先级）           │
│  → 谁需要？处于什么生命周期阶段？         │
│  → 需求强度如何？                        │
│  → 怎么判断谁需要？（数据 / 趋势 / 共鸣）│
├─────────────────────────────────────────┤
│  第二层：供给/内容视角                    │
│  → 现有图文/社区氛围中，有什么资源可以    │
│    转化为视频内容？                       │
│  → "有什么材料可以做饭"                  │
├─────────────────────────────────────────┤
│  第三层：生态视角（长期影响）             │
│  → 对互动率、平台调性、组织形态的影响     │
│  → 互动率下降后，平台还叫不叫原来的名字？ │
│  → 是否应该抽象到独立APP？还是在现有框架  │
│    内用商店形式展现？                     │
└─────────────────────────────────────────┘
```

### 3.2 关键注意点

- **主次关系必须清晰**：用户 → 内容 → 生态，不能平均用力。
- 如果三个层面都泛泛而谈，答案会变成"好像都做不了"，面试官不会满意。
- 生态层是加分项，不是基础分——校招/初级岗把用户和内容讲透即可。

### 3.3 简洁回答模板

> "先认定方向（视频化是趋势）→ 认定哪些人有需求 → 通过什么方法验证和满足需求 → 最终输出策略方案。"

## 四、策略PM核心胜任素质

### 4.1 四大核心能力

#### ① 强分析拆解逻辑

- 漏斗拆解能力
- 行业预估能力
- 数值预估能力（拍数字差距不大 = 加分项）

> "当你有一个很明确的数值预估，拍的差距不是太大的时候，我认为这个人是有 sense 的，会加分考虑。"

#### ② 前置业务认知与真实热爱

- 校招尤其看重：你是否真正理解并认同这个业务？
- 不喜欢 = 只是来打工，来了也不会用心做。
- 策略是"看不见摸不着"的东西，没有热爱很难坚持。

> "策略做的推荐或搜索，你能把握的工具很有限，只能通过一些细微的改变提升体验，这需要你在做之前就对这个事情有更深的感受。"

#### ③ 生态理解深度

- 决定你能否识别**负向指标**（不会死命追求单一数据）
- 决定你能否**协同多方**（数分、算法、运营、设计）
- 用统一的价值观把不同角色连接起来

> "如果你对生态理解准确，你会更容易把其他人连接起来；如果你只用数据推，反而在公司内部不好推。"

#### ④ 影响力与说服力

- 策略PM本质是 **"无实权的 FT Leader"**（中台型角色）
- 手上不握实权，开发人不是你，交互改动也需要别人配合
- 成功依赖：
  - **逻辑说服力**
  - **价值清晰传达**（"做完这个给你们带来什么价值"）
  - **"画饼 + 落地路径"**（既讲大愿景，也讲具体策略和漏斗预期）

> "产品经理最核心的是把目的讲清楚——目的讲清楚了，80%的问题都能解决。技术不懂、逻辑有漏洞，很多人可以帮你补；但价值讲不清楚，事情根本推不下去。"

### 4.2 策略PM vs 创新型产品PM

| 维度 | 策略PM | 创新型/工具型PM |
|---|---|---|
| 核心能力 | 在限制中发现价值 | 天马行空 + 落地 |
| 资源状态 | 限制多、资源少 | 相对灵活 |
| 价值体现 | 发现别人单打独斗发现不了的点 | 创造新场景/新模式 |
| 推动方式 | 逻辑 + 画饼 + 落地路径 | 愿景驱动 + 快速验证 |

## 五、面试表达与简历呈现要点

### 5.1 面试表达

- **前置抛出关键结论和量化结果**，再展开逻辑。
  - 例："我通过 XX 策略，提升了接单意愿 2.3pp"
  - 然后再讲"我是怎么发现这个问题的、怎么拆解的、怎么执行的"
- **不要过度追求严谨而丧失焦点**。
  - 面试不是写论文，重点是让面试官快速 get 到你的价值。
  - 先扔核心答案，再补充逻辑细节。
- **面试中的表达 ≠ 日常工作中的表达**。
  - 面试中：结论先行，重点突出，逻辑补充。
  - 工作中：可以更严谨地推演。

> 讲师原话："如果一直沉浸在自己的逻辑里往下推，面试官可能会失去谈话兴趣。"

### 5.2 简历呈现

- 体现 **"我主导的结果"**，即使不是亲手执行。
- 需要清晰说明：
  - 优先级设定
  - 策略制定
  - 跨角色协同（算法/运营/设计联动）
  - 最终归因
- **不要隐瞒数据**，真实性比保密更重要。
  - 模糊或回避数据 → 面试官可能质疑造假或没做过。
  - "你也不用为前公司做什么保密协议，他也不会给你更多的钱。"

### 5.3 简历描述示例

> "通过优化定价策略，测算关键卡点为 1 美金，1 美金以内/以上分别制定差异化策略；同时联动设计师优化价格展示 UI，最终实现接单意愿提升 2.3pp。"

### 5.4 常见误区

| 误区 | 正确做法 |
|---|---|
| "我跟着别人做的" | "虽然执行不是我做的，但所有优先级是我排的，策略是我定的" |
| 隐瞒具体数据 | 给出大致真实数据，哪怕是量级或比例 |
| 简历写得很牛，面试说得很谦虚 | 简历和面试的"影响力口径"要一致 |
| 只说自己做了什么 | 描述"我和团队是怎么做的"，体现协同能力 |

## 六、其他补充要点

### 6.1 脑筋急转弯/怪题（如烧绳子、赛马）

- 这类题多见于外企型面试官，国内公司基本只问务实题。
- 考察的是 **通用能力**：在不了解行业场景的情况下，如何快速做好拆解。
- 和咨询公司面试的 Case Study 类似。

### 6.2 策略PM的"拆东墙补西墙"困境

- 策略PM经常遇到：资源有限，好想法很多，但没有足够的"材料"来实现。
- 最惨的不是试错，而是**拆东墙补西墙解释不清楚**（如拼车单 vs 快车单的资源冲突）。
- 这不仅是面试问题，更是**工作中的核心挑战**——需要在日常工作中反复思考和打磨想法的可行性。

> "面试中的问题有 50%，其实在工作中就已经存在。"

### 6.3 策略PM的"小三"问题

- 策略经常面临资源竞争："谁是小三"——哪个业务/指标优先级更低？
- 需要明确立场："我更多是在保护我的业务，别动我的用户。"

## 七、总结速查表

| 维度 | 关键要点 |
|---|---|
| **面试评价** | 写客观可验证的硬伤（用户/策略/数据理解不足），不写主观感受 |
| **策略岗特点** | 宏观系统性思维、指标驱动、Case Study 为核心 |
| **业务题拆解** | 用户（优先）→ 内容/供给 → 生态（分层递进） |
| **核心素质** | 分析逻辑、业务热爱、生态理解、影响力/画饼能力 |
| **面试表达** | 结论先行、量化前置、重点突出 |
| **简历** | 体现主导权、写真实数据、展现协同能力 |
| **策略PM本质** | 无实权的 FT Leader，靠逻辑+价值+画饼推动协作 |
