## 五、面试问题与回答要点

### Q1：从零设计一个 AI 出行助手，如何覆盖用户预期？

**候选人的设计方案：**

```
用户出行助手 Agent 架构
├── 身份设定：明确为"身份助理"角色
├── 工具接入
│   ├── 内部工具：用户个人行程、旅程规划、出行安排
│   └── 外部工具
│       ├── 出行工具（如接入滴滴 Skill）
│       └── 天气工具（影响整体出行路线）
└── 工作流程
    ├── 收到任务 → 进行初步规划
    ├── 实时查询最新信息
    ├── 调用 Skill → 与用户确认最终方案
    ├── Agent 执行订票及落地安排
    └── 记忆沉淀 → 沉淀用户偏好，支撑个性化自进化
```

**思路亮点：** 参考了 Coze（扣子）等 Agent 平台的设计思路；内外部工具分层清晰；强调实时性与用户确认环节。

**增强方案：记忆沉淀机制（原方案未覆盖，作为补强）**

> 候选人的流程止于"执行订票"，是一次性规划。补一个**记忆沉淀**环节，把每次出行转化为 Agent 的长期记忆，让方案从"能用"升级为"越用越懂你"。

| 环节 | 动作 | 落地示例（出行场景） |
|------|------|------|
| **① 确认出行场景** | 与用户确认本次出行的场景归属 | "这次是通勤、商务出差、还是旅游？" |
| **② 记录用户偏好** | 沉淀本次决策中的选择与偏好 | 车型（专车/拼车）、时段、预算上限、规避项（如不坐某平台） |
| **③ 归类存储** | 按"场景 → 偏好"映射写入用户记忆库 | `商务出差 → 专车 / 预算宽松 / 准点优先` |
| **④ 自进化** | 下次规划时主动调取同场景记忆，优先匹配历史偏好 | 检测到商务出差，默认推荐专车方案，无需再问 |

**核心价值：** 形成正反馈闭环——每次确认喂养记忆，每次规划复用记忆。用户确认成本逐次降低，个性化程度逐次提升。
